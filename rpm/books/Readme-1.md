Основы программирования: Полный путь от идеи до работающего приложения
Давай разберём программирование как процесс — от того, как ты пишешь строчки кода, до того, как они превращаются в работающую программу у миллионов пользователей.

# 🧠 1. Что такое программирование

* Программирование — это процесс создания инструкций для компьютера на понятном ему языке.
Аналогия: Представь, что компьютер — это очень послушный, но глупый повар. Он умеет делать только то, что ты ему скажешь, и делает это буквально. Если ты скажешь "порежь лук", он будет ждать уточнений: каким ножом? на какой доске? кольцами или кубиками?

* Программа = набор таких инструкций, написанных по строгим правилам.
* Уровни языков

````Высокий уровень (близко к человеку)
    ↓
    Python: "отправь email пользователю"
    ↓
Средний уровень
    ↓
    C: "открой сокет, сформируй пакет, отправь"
    ↓
Низкий уровень (близко к машине)
    ↓
    Ассемблер: "загрузи в регистр AX значение 0x4F"
    ↓
Машинный код (нули и единицы)
    ↓
    01001000 01100101 01101100 01101100 01101111

````

Чем выше уровень — тем проще писать, но тем меньше контроля над железом.

# 💾 2. Где хранится код

* 2.1. Локально (на твоём компьютере)
Код — это обычные текстовые файлы. Ты можешь открыть их в блокноте.

````
/home/user/my_project/
├── main.py              ← Python-код
├── app.js               ← JavaScript-код
├── config.yaml          ← Конфигурация
├── README.md            ← Документация
└── tests/
    └── test_main.py     ← Тесты
````

* 2.2. В системе контроля версий (Git)

Когда код пишут несколько людей или нужно хранить историю изменений, используют Git.
Репозиторий — это папка с кодом + вся история его изменений.

````
# Создаём репозиторий
git init

# Добавляем файлы
git add .

# Фиксируем изменения (создаём "снимок")
git commit -m "Добавил функцию отправки email"
````

Каждый commit — это снимок всего проекта в определённый момент времени. Ты можешь вернуться к любому снимку.

* 2.3. На удалённом сервере (GitHub, GitLab, Bitbucket)

Локальный репозиторий хранится только у тебя. Чтобы код был доступен команде, его пушат на удалённый сервер:

* Отправляем свои изменения на сервер

````
git push origin main
````

Популярные хостинги:
````
Gitlab
GitHub
BitBucket
Gitea
````

# 🔄 4. Жизненный цикл кода (от идеи до продакшена)

Это самый важный процесс. Вот как код попадает к пользователю:
````
┌─────────────┐
│  1. Идея    │  "Нужна функция отправки email"
└──────┬──────┘
       ↓
┌─────────────────────────────┐
│  2. Написание кода          │  Разработчик пишет в IDE (VS Code, PyCharm)
│     (локально на компьютере)│
└──────┬──────────────────────┘
       ↓
┌─────────────────────────────┐
│  3. Тестиров локально       │  Запуск, отладка, проверка
└──────┬──────────────────────┘
       ↓
┌─────────────────────────────┐
│  4. Коммит в Git            │  git commit -m "Add email feature"
└──────┬──────────────────────┘
       ↓
┌─────────────────────────────┐
│  5. Push в репозиторий      │  git push → код попадает на GitHub/GitLab
└──────┬──────────────────────┘
       ↓
┌─────────────────────────────────────────────┐
│  6. CI/CD пайплайн (автоматизация)          │
│  ┌──────────────┐  ┌──────────────┐         │
│  │ Build        │→ │ Test         │         │
│  │ (сборка)     │  │ (проверки)   │         │
│  └──────────────┘  └──────┬───────┘         │
│                            ↓                 │
│                    ┌──────────────┐          │
│                    │ Deploy       │          │
│                    │ (развёртка)  │          │
│                    └──────────────┘          │
└─────────────────────────────────────────────┘
       ↓
┌─────────────────────────────┐
│  7. Работа в продакшене     │  Пользователи пользуют
└──────┬──────────────────────┘
       ↓
┌─────────────────────────────┐
│  8. Мониторинг              │  Prometheus, Grafana, логи
└──────┬──────────────────────┘
       ↓
┌─────────────────────────────┐
│  9. Новая итерация          │  Возврат к шагу 1
└─────────────────────────────┘
````

# 📦 5. Сборка кода (Build)

* Контейнеризация (Docker)
Современный стандарт — упаковать приложение вместе со всеми зависимостями в контейнер.
Dockerfile — инструкция по сборке:

````
FROM python:3.11
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "main.py"]
````

Сборка образа:
````
docker build -t myapp:1.0 .
````

Запуск:
````
docker run -d -p 8080:8080 myapp:1.0
````

# 🚀 6. CI/CD — автоматизация всего процесса

* CI (Continuous Integration) — непрерывная интеграция. Автоматическая проверка кода при каждом коммите.
* CD (Continuous Delivery/Deployment) — непрерывная доставка/развёртка. Автоматический деплой после успешных тестов.

* Популярные CI/CD системы
 - GitLab CI — встроен в GitLab, YAML-конфиги
 - GitHub Actions — встроен в GitHub
 - Jenkins — старый, но мощный
 - ArgoCD — для Kubernetes
 - TeamCity — от JetBrains

````
stages:
  - test
  - build
  - deploy

test:
  stage: test
  script:
    - pytest tests/

build:
  stage: build
  script:
    - docker build -t myapp:$CI_COMMIT_SHA .
    - docker push registry.example.com/myapp:$CI_COMMIT_SHA

deploy:
  stage: deploy
  script:
    - ansible-playbook -i inventory deploy.yml
  only:
    - main
````

* Что происходит:
Ты делаешь git push
GitLab автоматически запускает тесты
Если тесты прошли — собирается Docker-образ
Образ пушится в registry
Если это ветка main — Ansible разворачивает на серверах

# 🏗️ 7. Архитектура приложений

Монолит
Всё в одном приложении.

````
┌──────────────────────┐
│   Один большой код   │
│  (веб + БД + логика) │
└──────────────────────┘
````

Плюсы: Просто деплоить, легко отлаживать.
Минусы: Трудно масштабировать, одно падение роняет всё.

* Микросервисы
Много маленьких независимых сервисов.
````
┌─────────┐  ┌─────────┐  ┌─────────┐
│ Сервис  │  │ Сервис  │  │ Сервис  │
│   A     │  │   B     │  │   C     │
└────┬────┘  └────┬────┘  └────┬────┘
     └────────────┼────────────┘
                  ↓
            ┌──────────┐
            │ API GW   │
            └──────────┘
````

Плюсы: Масштабируется, независимые релизы.
Минусы: Сложно управлять, нужна оркестрация (Kubernetes).

# 🎯 10. Главные принципы программирования
 - KISS (Keep It Simple, Stupid) — делай просто
 - DRY (Don't Repeat Yourself) — не повторяйся
 - Идемпотентность — повторный запуск даёт тот же результат (привет, Ansible!)
 - Тестируй код — без тестов код мёртв
 - Документируй — через месяц ты не вспомнишь, зачем это написал
 - Версионируй всё — код, конфиги, инфраструктуру (Git, Terraform)
